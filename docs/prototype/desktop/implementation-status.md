## 已实现

### 传输与会话

- loopback bridge：只绑回环、nonce cookie（HttpOnly + SameSite=Strict）、Host 校验、前缀白名单、显式拒绝 `/api/app/`、不返回 CORS 头、强制覆写 Origin。七条约束都写成了测试。
- 一次性入口令牌：`EntryURL()` 换 cookie 后立即作废，且只在成功时作废。
- Wails IPC 经资产中间件注入 bridge，`/wails/runtime` 走同源校验；未接线时 501 而非 404。
- 实例连接与探活：以 `GET /api/v1/client-compat` 为主判据，根路径仅对老实例兜底且要求响应非 HTML。
- 登录、refresh（全局 single-flight）、登出、实例切换；refresh token 只进系统钥匙串，`Credentials` 结构里不含该字段。
- **联网 git 命令取的是"新鲜"令牌**：`FreshAccessToken` 读 JWT 自己的 `exp`，临期就先经 single-flight 刷新再交出去（详见"本地 Git"一节）。刷新失败时退回内存里那枚而不是清空——"可能过期"不等于"确定过期"，直接判定登录失效会把一次本可以成功的推送变成一次重新登录。
- **首次使用的三步引导在一页内完成**：连接实例 → 登录 → 克隆，不拆成三个路由。步进由状态机（`lib/onboarding.ts`）算而不是靠按钮跳转：实例不可达或契约过旧就停在第一步，此时登录框是禁用的——先让用户填密码再回一句"登录失败"等于把已知原因藏起来。已完成的步骤折叠成一行摘要，随时可点开重做；已有实例档案时第一步变成可选列表，不必回空表单重敲地址。版本过旧是**阻断式**的：`ConnectForm` 只有 `reachable && !instanceTooOld(info) && id` 才算连接成功（这里此前注释声称阻断、代码却放行，已对齐）。
- **登录框的可用性靠现探判定**：实例档案只存名称与版本号，没有契约信息，所以引导页用 `useInstanceProbe` 打一次 `/client-compat`（30 秒缓存）来决定第二步能不能解锁。
- **克隆可跳过**：只想翻 Inbox 的人不该被迫下载仓库，第三步给"跳过"，`ready = hasWorkingCopy || cloneSkipped`。登录后的默认落点仍是克隆。

### 本地 Git

- 只用系统 git 可执行文件，不引入 go-git。
- 读取用 `--porcelain=v1 -z` 与 `--numstat -z`，关闭 `core.quotepath` 以支持非 ASCII 路径。
- 状态（分支 / dirty / ahead / behind / 变更列表）、暂存、取消暂存、提交、fetch、push。
- 逐 hunk 暂存与取消暂存：按 hunk 头从当前 diff 切出"文件头 + 单块"的最小 patch，用 `git apply --cached` 写进 index。hunk 头同时充当陈旧性校验——界面列表是快照，重新读到的 diff 里找不到它就报错让界面刷新，不做"就近猜一块"。未跟踪文件与重命名区段明确拒绝并指向整文件暂存。
- 半暂存状态可表达：同一文件可以一半在 index、一半在工作树（porcelain 的 `MM`），`Change.HasUnstaged` 让它在列表两侧都能出现。
- 强制 push 用 `--force-with-lease`，需二次确认并展示完整命令。
- 同一工作树的 git 调用在进程内串行化，避免用户看到 `index.lock exists`。
- 相对 HEAD 的读取有三条：`HeadDiff`（`git diff HEAD --`，含已暂存与未暂存）、`HeadText`（`git show HEAD:<path>`，取原文给编辑器逐行比较）、`Blame`（`git blame --line-porcelain`）。`HeadText` 在路径不在 HEAD 里时返回 `Exists=false` 且不报错——新文件在编辑中是常态。
- 提交与推送失败走居中弹窗：git 的原始输出原样放进可滚动的等宽区域，配一个复制按钮。这类输出常常是多行、带缩进的操作提示，塞在按钮下面既挤断布局又没法复制。
- **克隆有两个来源**：本实例的仓库列表（`GET /api/v1/repositories`，用内存里的 access token）与任意 git URL（交给用户自己的 git 配置）。地址拼接只在 Go 侧做——前端只传 `owner/repo`，`git.InstanceCloneURL` 校验形状（拒 `.`/`..` 段、拒重复 `.git` 后缀、只接受 http/https）。地址决定"能让 git 去访问什么"，让界面拼就等于把这件事交给最不该管的一层。
- **凭据走 Bearer，不走 Basic**：`http.<完整仓库 URL>.extraHeader=Authorization: Bearer <token>` 经 `GIT_CONFIG_*` 环境变量注入（不上命令行，`ps` 看不到），同时 `credential.helper=` 清空，避免 GCM/钥匙串在无终端环境里弹窗、挂死。Basic 形态试过不成立：`git_auth_controller` 的 Basic 分支校验的是账号密码，access token 当密码会被拒；Bearer 分支才是令牌的入口。作用域收到**具体仓库**而非主机：前缀同名的另一个仓库实测拿不到这个头。
- **外部 URL 不注入凭据**：`git.ValidateRemoteURL` 拒空白、拒带密码的地址（带密码的 URL 会被 git 写进 `.git/config` 的 origin），scp 形式单独校验用户名段；这类 clone 继承用户自己的 git 环境。
- **克隆的进度与取消**：`git clone --progress` 的 stderr 按 `\n` **或 `\r`** 切分（进度用 `\r` 原地刷新，只按 `\n` 切会让百分比停在最后一次），解析成 `{phase, percent}` 经 Wails 事件 `clone:progress` 推到界面。取消 = cancel context → 杀进程 → **只删自己创建的那个目标目录**；目标已存在时直接拒绝（`ErrTargetExists`）且不动原有内容。失败时保留 git 的最后几条原文而不是一句"克隆失败"。
- **目标目录一律由用户选，桌面端不给默认值**。位置通过系统目录选择框指定（`CanChooseFiles(false)` + `CanChooseDirectories(true)`，Wails 默认是选文件的）；没选位置时克隆按钮保持禁用，位置行显示"请选择一个位置"。放弃自动选址是刻意的：机器上哪块盘可写、哪块盘够大，只有用户知道；替用户挑一个再撞上权限或空间不足，报错只会变成"它自己想放的地方放不了"。克隆完成后复用 `Add` 的登记逻辑并设为活动仓库——另写一份归一化逻辑只会漂移。
- **权限失败翻译成人话**：`os.MkdirAll` 的 `Access is denied` 与 git 自己的报错都收成一句"没有权限在 X 下创建目录，请换一个位置"。Windows 上要额外比 `syscall.ERROR_ACCESS_DENIED`——`*os.PathError` 里包的是 `syscall.Errno(5)`，部分 Go 版本里它并不等于 `os.ErrPermission`。界面侧先剥掉绑定层加的 `RuntimeError:` 前缀再匹配，否则同一句话在两端会长得不一样。
- **联网命令的凭据与克隆共用一套注入**：`git.Push` / `git.Fetch` 走 `NetworkEnv`，与 `cloneEnv` 同一份实现（`GIT_CONFIG_*` 里的 `http.<远端>.extraHeader` + 清空 `credential.helper` + `GIT_TERMINAL_PROMPT=0`）。此前只有 clone 带凭据，于是"用引导克隆了仓库、什么也没配"的用户第一次 push 会被要凭据——坑是桌面端自己挖的。
- **注入与否按"这条命令真正访问的远端"裁决**，判据是**仓库路径前缀**而不是主机名：`remoteMatchesInstance` 要求 scheme/主机/端口一致且实例路径是远端路径的前缀（边界必须落在 `/`，否则 `example.com/git` 会认领 `git-fastlab/repo`）。按主机匹配会把同主机上的别人仓库、共存的其他 git 服务一起当成自己人散令牌。只认 http/https：ssh 写法与本地路径回落到用户自己的凭据体系，Bearer 对它们本来就不适用；带 userinfo 的远端一律拒绝，那说明有人把凭据写进了地址。作用域取 `git remote get-url` 的原样输出而不是拼接结果——用户可能 set-url 改写过写法，只有原样输出与 git 实际发出的请求对得上。
- **令牌在发起前保证新鲜**：`FreshAccessToken` 读 JWT 自己的 `exp`（只解码不验签——用途是"什么时候该换一枚"，授权判断永远在服务端），临期就走既有 single-flight 刷新。HTTP 请求有 401 重试兜底，git 子进程没有：带上过期令牌只会换来一句用户看不懂的认证错误。`exp` 解不出来时不强制刷新，先用现有令牌试一次。联网命令上限 3 分钟、令牌有效期 30 分钟，因此不需要中途轮换。
- **push 的计划只算一次**：`PlanPush` 同时给出「跑什么参数」「确认框显示什么」「碰哪个远端」，`PushCommand` 与 `Push` 共用它。破坏性操作的确认一旦与执行对不上，整个闸门就白做。
- **分支没有上游时推同一条终端会建议的命令**：`git push --set-upstream origin <分支>`，而不是把 git 那句 "no tracking information" 甩进错误弹窗。远端名按 git 自己的优先级解析（`branch.<name>.pushremote` → `remote.pushdefault` → origin → 第一个远端），且要求该远端真实存在。拿不到分支名（游离 HEAD、空仓库）或根本没有远端时退回裸 `git push` 让 git 报错——猜一个分支名去推，可能把提交落到用户没打算碰的分支上。
- **顺带修掉一个既有缺陷**：`remoteNames` 早期一遇到 `origin` 就直接返回，把字母序排在它之后的远端（`upstream` 恰是最常见的第二个）整个丢掉，表现为"明明配了 upstream，程序却说这仓库只有 origin"。

### 编辑器（Code 面）

- 文件树逐层列举，目录在前并带变更标记；文件/内容/符号/变更四段；路径过滤走 `SearchFiles` 并做去抖，内容段是工作树全文搜索（见「全文内容搜索」）。
- 标签页可关闭并把焦点落到相邻标签，未保存的带圆点标记。圆点只表示"内容与磁盘不同"：编辑器把外部内容摆上去时也走同一条 `docChanged` 通道，因此同步用的 dispatch 带一个标注，监听器据此区分程序化写入与键盘输入——否则切一次标签就会多一个圆点。
- CodeMirror 6 + 按需加载语言包，语法高亮；`@kustos/editor` 包与 Web 端共用。
- `⌘S` 写盘；磁盘在编辑期间被外部改过时拒绝写入并提示，由用户选择是否覆盖。
- 换行符按文件原样保留：CodeMirror 的文档模型只存 `\n`，读入时记下磁盘用的是 LF 还是 CRLF，保存时再还原回去；判断"改没改"也在归一后比较，避免 CRLF 文件一打开就被当成改过。
- 写盘先写临时文件再改名，保留原文件权限位。
- `⌘P` 快速打开，按路径匹配、键盘选择。
- 崩溃恢复：未保存内容按（工作副本，路径）落到 `buffer_recovery` 表，重开后提示「恢复 / 丢弃」，不自动套用。
- 标签页布局恢复：打开的标签（含顺序）、当前文件与展开的目录落 `ui_state` 的 `code.layout` 一条，切回仓库或重开应用时原位复原。只保一份、记录里带工作副本 id，对不上就整份作废——`ui_state` 没有过期清理，按仓库存会留下永远读不到的记录。写入去抖 400ms，窗口隐藏/关闭时立即落盘。切到空仓库不会清掉上一个仓库的记录。
- 外部编辑器互跳与在文件管理器中定位。
- **diff 行标**：编辑器左侧 4px 色条标出相对 HEAD 的新增（sage）、改动（sky）与删除（rose，挂在删除位置之后那一行）。基准取 HEAD 而不是索引——用户的心智基准是上次提交，不是他刚才 stage 过什么。行标与**当前缓冲区**逐行比较（`HeadText` 取 HEAD 原文，`lib/head-diff.ts` 做 LCS 对齐），因此打字时标记跟着实时移动；换成拿文本 diff 对齐，缓冲区一脏就整体错位。纯逻辑可单测，不依赖编辑器。
- **blame 行**：顶栏「Blame」开关，每行显示作者缩写；未提交的行显示 "uncommitted" 并用琥珀色斜体标出。取 `git blame --line-porcelain`（每行都带完整作者信息），时间统一毫秒跨进程边界。开关打开时工具栏下多一条当前光标行的归属：作者、短哈希、提交标题与相对时间。数据随开关懒加载，关掉就不注入 gutter——挂着一条 84px 的空条看起来像界面漏了一块。
- 行标与 blame 都做成 CodeMirror 扩展、经共享包 `@kustos/editor` 的同一个扩展插槽注入：数据不通过 props 传，而是由 React 侧持有一个数据源、编辑器侧订阅后用 `StateEffect` 推进状态。注入的扩展数组保持稳定，编辑器才不会因为重渲染丢掉内部状态。
- **全文内容搜索（左栏「内容」分段）**：调 `git grep` 现扫工作树，**不建本地索引**。设计文档原本设想 SQLite FTS5 索引，实现时改了裁决，理由有三条，都写进了 `internal/git/grep.go` 的包注释：桌面端刻意没有文件监听，一份会过期的索引搜出来的行号会跳到不存在的位置——搜索结果的错误比搜索慢更致命；`.gitignore` 语义免费（自建索引要么重实现 ignore 规则，要么把 node_modules 整坨吸进来）；`git grep` 的结果就是用户在终端里能复现的结果。范围是"被跟踪 + 未跟踪但未忽略"（`--untracked`），被忽略的文件不搜。默认按字面量匹配（输入 `fn(x)` 不该被当正则），`re` 开关切扩展正则，`Aa` 开关切大小写敏感；目录范围框把搜索收窄到某个子树，路径同样收敛在仓库内、不存在的目录报错而不是空结果。
- **结果列表按文件分节**：几十条命中平铺时，"集中在哪几个文件"这个最重要的信息反而看不见。每行带命中片段高亮，点一条 = 打开那个文件并跳到那一行。目标文件还没读回来时行号先挂着（`pendingJump`），等内容落地那一帧再交编辑器——直接 `revealLine` 会拿着上一份文档的行数做钳制，跳到错的位置。
- **截断与上限要说出来**：总命中上限 500、单文件上限 50（一个 lock 文件不该吃光整个配额，让别的文件一条都进不来）。触顶时列表顶部明示"已满，请缩小查询"，而不是让用户以为整个仓库只有这些。解析是流式的：读满配额直接杀进程，宽泛查询的几百 MB 输出不会先进内存再截断。没有命中是空结果不是错误（git 的退出码 1），非法正则则是错误——"仓库里没有"与"表达式写错了"必须分得开。单字符查询被挡住（至少要 2 个字符），空查询不发起扫描。

### 本地智能

- **进程池**（`internal/lsp`）：每个工作区根一个语言服务器进程，上限 3 个、空闲 10 分钟回收、崩溃按 1s / 2s / 4s 退避重启，三次失败后停在 `failed` 并保留最后一次 stderr 尾部作为原因。进程归 Go，协议归前端：池子只管"拉起来、转发帧、盯着退出"，不认识任何 LSP 方法。
- **帧协议**：按 `Content-Length` 头逐帧读写，不是按行切；头长与帧长都有上限（4 KiB / 64 MiB）。stderr 单独抽干到环形缓冲，否则子进程写满管道会自己卡死。
- **`ws ↔ stdio` 转发**：`/lsp/attach?root=<绝对路径>`，走 bridge 的 `/lsp/` 前缀到进程内处理器，不再是反代目标。准入判断在 WebSocket 升级之前完成——握手一旦成功客户端就能发任意 LSP 请求。客户端发裸 JSON 或带帧头的消息都接受。
- **workspace trust**：语言服务器会执行工作区里的代码（解析导入、加载 `package.json`、跑 `go list`），因此首次打开工作副本要先确认一次。信任记在 SQLite 的 `workspace_trust` 表（键是收敛后的绝对路径），未信任时既不启动服务器，编辑器也退回只读、`⌘S` 与保存按钮禁用；撤销信任会顺手停掉正在跑的进程。
- **信任绑定远端来源**：信任记录同时存下做决定时的 `origin`。语言服务器执行的是"这个目录里来自某个远端的代码"，把 `remote` 改指到另一个仓库之后，同一个目录里的代码就换出处了，旧的点头不再生效——再问一次，并且状态条要说清"远端换成了哪个"。任一侧为空（旧版记录、本地仓库还没配远端）都按来源未变放行，升级不会把所有既有信任一次性作废。发现换源时顺手停掉已经在跑的进程。
- **语言探测**：按仓库根的 marker 文件判定，TypeScript / Python / Go / Rust 四种；服务器不在 PATH 上时只给出安装命令与"重新探测"，不静默下载二进制。
- **状态条**：信任确认、没探测到语言、服务器未安装、启动中、重启中、已停止重试、运行中各自一句话，不把它们合并成"未就绪"——四种状态用户该做的下一步完全不同。
- **编辑器侧**（`lib/lsp-client.ts`）：用 `@codemirror/lsp-client`，自己实现一个 WebSocket `Transport` 与一个 `Workspace` 子类。只有"连上哪个 client + 打开哪个文件"变化时才重建插件，否则每帧重发 `didOpen`/`didClose`。跨文件跳定义要靠 `displayFile`——它把 LSP 的 `file://` URI 换回仓库相对路径、让 Code 面打开那个标签，等编辑器挂载后再把 `EditorView` 交还给客户端（2 秒超时后退回"跳不过去"）。`symbols` 分段取 `textDocument/documentSymbol`，点条目跳到对应行。共享包 `@kustos/editor` 只开一个扩展插槽，不依赖任何 LSP 包：语言服务器连接是桌面专有的。
- **跳定义打不开时说明原因**：语言服务器常把定义指到仓库外（Go 标准库、`node_modules`），桌面端打不开那个文件。此前一律静默返回 null，表现与"这个符号根本没有定义"完全一样。`classifyDisplayTarget` 把结果分成 `outside-root` / `not-file` / `root-itself` / `timeout` 四种，编辑器上方给出带目标路径的提示，几秒后自己消失——这是一次性回执，不是持续故障。

### 深链与系统集成

- **深链只做"打开某一屏"**：`kustos://code` 这类分区深链落到对应界面，`kustos://review/<仓库 id>|<PR 编号>` 还会开评审窗。它同时是**跨信任边界**的输入——任何本机进程都能伪造一条，因此解析只认白名单里的五个分区，非法形状一律报错而不回落到默认屏：一条打不开的链接应当能被发现，悄悄打开 Inbox 会让人以为链接生效了。
- **评审深链带仓库 id**，因为 PR 编号只在仓库内唯一：只带编号会把 A 仓库的 #3 打开成 B 仓库的 #3。分隔符用 `|`，两种写法（原样与 `%7C`）等价。
- **参数到达的时机要兜两次**：第二实例启动时 `handleSecondLaunch` 收到 `kustos://` 参数就投递；首次启动也能从 `os.Args` 里认出来。前端一侧既订阅 `deeplink:navigate` 事件，**启动后还主动调一次 `PendingSurface`**——深链可能在窗口刚创建、监听器还没注册时到达，那时广播没有任何接收者。
- **协议注册与开机自启写用户自己的注册表（HKCU）**，不写 HKLM：桌面端是按用户安装的普通程序，写 HKLM 要弹 UAC，而"装个编辑器还要管理员授权"会让人直接放弃。权限掩码取 `SET_VALUE | CREATE_SUB_KEY`——`ALL_ACCESS` 会连带请求只属于管理员的能力（实测普通用户进程直接得到 `Access is denied`），而只给 `SET_VALUE` 又建不出多层子键。
- **两项都做成设置面的显式开关，而不是装完就悄悄写**。设置面（左轨底部齿轮）只放"与实例、仓库都无关的本机偏好"；齿轮此前是个点了没反应的按钮，现在有了去处。
- **查现状比"键存在"更严**：`ProtocolRegistered` / `AutostartEnabled` 要求注册值指向**当前这个可执行文件**。程序升级或换了安装位置之后，旧注册项指向一个不存在的路径，点链接的表现是"什么都没发生"——那算没注册对。
- **开机自启的启动项名称取产品名 `Kustos`** 而不是可执行文件名：用户会在任务管理器的启动项里看到它。

### 本地存储

SQLite（`modernc.org/sqlite`，纯 Go，无 CGO），迁移共 7 版：

| 版本 | 表 |
| --- | --- |
| v1 | `instances` |
| v2 | `ui_state` |
| v3 | `working_copies` |
| v4 | `buffer_recovery` |
| v5 | `workspace_trust` |
| v6 | `workspace_trust.origin`（信任绑定远端来源） |
| v7 | `offline_cache`（只读数据的离线缓存） |

- **离线缓存只存只读数据**：Inbox、PR、Issue 的响应按查询标识存一份 JSON 加取回时间。能写的东西（草稿、提交）另有自己的表——用"恢复一份旧 JSON"冒充写成功就是静默的数据丢失。
- **缓存挂在 React Query 的事件上而不是逐查询 `onSuccess`**：需要缓存的查询有十几处，逐个接线一定会漏几个，而"漏掉的那个断网就空白"是最难被发现的失败。缓存的键由 `queryHash` 映射而来，避免手写 key 与查询参数不一致时把 A 的响应写到 B 的缓存里。
- **回落只在在线请求确实失败时发生，并且要说出来**：界面标明"显示的是什么时候取回的缓存内容"——不标这一句，用户会把几天前的 Inbox 当成现在的状态。
- **保留窗口七天，启动时清理一次**：缓存攒着几个月前的响应既占空间，也让"离线时看到的是什么时候的数据"更难回答。单条内容上限 8 MiB。

启动期的失败处理：日志落到数据目录的 `desktop.log`，致命错误弹窗说明原因（`KUSTOS_DESKTOP_NO_DIALOG` 可在自动化里关掉）；本地库打开失败先重试，损坏才改名隔离后重建。

### 界面

- 无边框窗口 + 前端自绘标题栏；拖拽区与窗口控制键按 `--wails-non-client-region` 标注。
- 三栏外壳：标题栏（仓库/分支 chip、ahead/behind）、左轨、可拖拽列表栏、状态条。
- 命令面板 `⌘K`：输入过滤、跨组 ↑↓ 游标、`↵` 执行、`Esc` 关闭；标题栏搜索框同入口。只列当下真能执行的动作（七个 surface 跳转、快速打开文件、在外部编辑器中打开当前文件、进入/退出协作）——前提不满足时整组不出现，而不是渲染成禁用态。
- 七个 surface 中已接真实数据：Inbox、Working copy、Code、Pull requests、Issues。Chat 与 Agent 保持骨架空态。
- 中英双语（i18next），资源与 Web 端独立，键一致性有测试。

### 多窗口与托盘

- **多窗口**：窗口按 `Name` 复用（`main` / `review`），`OpenWindow` 对已存在的窗口只唤到前面，不重复创建。每种窗口各自持有一份几何状态（`window.main` / `window.review`），复用的是既有 `windowstate` 包。
- **评审窗是真正的第二个窗口**：它显示单个 PR，且**没有左轨与列表栏**——打开它是"把某个 PR 拎出来单独看"，再放一层列表只会让人以为能在窗口里切换 PR。PR 定位经 URL 片段（`#/review/<仓库 id>|<编号>`）随窗口自己走，而不是靠全局状态：多窗口下全局状态由最后写入者胜出，两个评审窗会显示同一个 PR。片段里带仓库 id 是因为 PR 编号只在仓库内唯一，只带编号会把 A 仓库的 #3 打开成 B 仓库的 #3；分隔符用 `|` 而非 `/`，因为片段本身按 `/` 切分。对已存在的评审窗再次打开另一个 PR 会替换内容并重新导航。
- **窗口内容由片段决定，且每种窗口都带着自己的片段**：`window-route.ts` 解析片段得到这一屏该渲染什么，`app.tsx` 在会话就绪后按它分流（评审窗不进主界面外壳）。评审窗即使还没有 PR 也带 `#/review`——托盘菜单直接唤出的就是这个状态，缺了片段前端无法把它和主窗口区分开，只会渲染出第二个 Inbox。空态给出"回主窗口选一个 PR"的指引。同窗口内改片段靠 `hashchange` 跟进。
- **评审窗照原型 `docs/prototype/desktop/review.html` 还原**：左侧是 PR 头 + 整份 diff + 草稿条，右侧是 340px 的对话/检查面板，底部是合并闸口。逐文件头带 `+N`/`−N`、状态字母与"已查看"开关（只看本机，不回传）；单栏/双栏可切换，双栏按块把删除行与新增行配对。文件级 `+N`/`−N` 由整份 diff 文本按文件切开后逐段统计——服务端 `files[]` 只给 `{status, path, old_path, status_code}`，没有计数。
- **行内意见挂在"新文件侧行号"上**：提交时后端拿到的就是这个行号。删除行没有新行号，而它的旧行号可能与某个新增行同号（把第 1 行整行替换掉时，`-旧` 的 old = 1、`+新` 的 new = 1），此时锚点归新文件侧那一行，删除行让出——否则一条意见会在两行下面各渲染一次、草稿开出两个输入框。判定在 `diff-anchor.ts`，有回归用例。
- **草稿先落本机再提交**：`POST /reviews` 只收一条 `comment`，多条评审意见无法原子提交，所以草稿攒在本地（localStorage，按实例 + 仓库 + PR 分域），提交时逐条发 `POST /comments`。原型底部那排是"保存草稿 / 提交评审"，这里换成"丢弃草稿 / 提交意见"——草稿产生时就已经落盘，不需要再存一次。投票是独立动作，走 `POST /reviews`；对自己的 PR 投会被服务端以 `pr_self_approve_forbidden` 拒绝。
- **检查面板不编造**：本平台没有 CI，`evaluate_status_checks` 恒真，所以"检查"页只显示"这个实例没有接入 CI"与真实的分支保护规则（是否受保护、是否需要代码评审、是否需要状态检查）。原型里那三行 `build` / `pytest` / `web e2e` 没有数据来源，不照着画。
- **关窗语义**：主窗口关闭是收进托盘（`RegisterHook` + `Cancel` + `Hide`），不是退出；退出是托盘菜单里的显式动作。评审窗关闭就是真关闭。这一条必须用 `RegisterHook` 而不是 `OnWindowEvent`——前者在 UI 线程同步执行，`Cancel` 才能挡住 Wails 内建的销毁流程；后者在独立 goroutine 里，拦不住。
- **托盘**：内嵌 PNG 图标（非 PNG 会在 Windows 上静默不显示，有测试守着），菜单为「打开 Kustos / 评审窗 / 退出」，单击图标唤出主窗口。Wails 要求托盘在 `app.Run()` 之后创建，早于事件循环创建则托盘根本不出现。
- **入口令牌按窗口发放**：每个窗口导航时各取一个一次性令牌。只留单个令牌时，后开的窗口会把前一个顶掉，表现为「开第二个窗口，第一个白屏」。
- 窗口里放什么仍由服务端裁决；Go 侧只回答「本机有几个窗口、能不能再开一个」。

### 协作

- **一个文件一个真相**：`doc-mode.ts` 定义三态 `disk` / `live` / `observe` 与迁移规则。`disconnect` 不改变模式——Y.Doc 离线仍可编辑、重连自动合并，把它当成退出协作会让用户以为刚写的字丢了；界面用琥珀色"离线，改动留在本地"表达，而不是红条。
- **`live` 下不写磁盘**：编辑器的 `onChange` 在协作模式被摘掉，内容只进共享文本；退出协作时把共享文本一次性写回缓冲区并标脏，由用户决定要不要 `⌘S` 落盘。`⌘S` 的含义随模式变（写盘 / 存草稿 / 什么都不做），所以模式徽标常驻在 ed-bar 上。
- **挂载顺序是硬约束**：`y-codemirror.next` 的同步插件既不用共享文本初始化 CodeMirror，也不会把 CodeMirror 写进共享文本（读源码确认：构造只 `ytext.observe`，`update` 里把任何非本插件标注的 `docChanged` 推给 Y.Text）。因此进入协作必须**先有会话、再挂编辑器**，并给 `CodeView` 换 `key` 强制重建；否则磁盘内容会被当成"本地新增"整段插进共享文档。`CodeView` 的 `syncContent` 在协作模式关掉，避免两份真相互相覆盖。
- **四步预检**（`precheck`）：分支对齐、本地改动、在线草稿、在线人数。前两步阻塞（决定"本地有没有会丢的东西"），草稿领先只是提示，人数未知则只封 `seed`——感知降级时把空清单当成"没人在线"是最危险的误判。阻塞项里还单列**缓冲区未写盘的改动**：git 看不见它，提交也带不走，直接进协作会被共享文本顶掉。
- **预检只摆真能执行的处置**：提交本地改动（暂存 + 提交，带可编辑的提交信息）、写盘并继续、只读观察。切分支 / stash / 放弃改动在 Go 侧还没有对应能力，界面只给一句提示让人去工作副本面或本地 git 处理，不画点了没反应的按钮。
- **协作感知**：`GET /repositories/{id}/collab/active` 15 秒轮询，按分支收敛成"每个路径几个人"，文件树据此给文件打 `live` 圆点（hover 显示"2 人正在编辑"）。响应区分 `documents` 与 `degraded`，降级时不显示圆点也不拿它当"没人在线"。
- **保存落草稿分支**：`⌘S` 在 `live` 下发 stateless `collab-save`，网关把它存成 `collab/draft-{branch}` 的一次提交；状态条写明草稿分支名，并只在收到网关 `collab-saved` 广播后才显示"已存成 &lt;commit&gt;"——乐观显示会在断线时说谎。
- **草稿领先以服务端为准**：界面上"还有 N 次未发布"取 `GET /{repo_id}/compare`（`base`=目标分支、`head`=草稿分支）的 `ahead_by`，协作模式下 30 秒重取一次，发布成功后立刻重取归零。`DraftAhead`（Go，`git rev-list --count`，不联网）只在进入协作前的预检里用——那里不该为一句提示动网络。两处口径必须一致：`DraftAhead` 已改成草稿与基准同侧（草稿命中 `origin/collab/draft-{branch}` 就拿 `origin/{branch}` 当基准），否则本地分支落后远端时会把别人的提交算成自己未发布的，而这个数字就写在按钮上。
- **发布走独立确认框**：`POST /{repo_id}/collab/publish` 把草稿侧全部变更 squash 成目标分支上的一次提交。发布前用 `GET /{repo_id}/compare`（`base`=目标分支、`head`=草稿分支）摊开"要合进去的是什么"——提交数、逐文件增删。草稿上可能是别人攒了一下午的保存，看不见内容就点发布等于盲签；这也是桌面端相对 Web 多做的一步。服务端返回 `commit_id=null` 表示无待发布内容，界面照实说"没有产生新提交"而不是报成功。
- **发布成功不退出协作**：发布只是把攒下的保存落到正式历史，编辑会话不必因此中断。要收的是"草稿还有 N 次未发布"的提示与那条已失效的"已存成 &lt;commit&gt;"回执——那次提交已经被 squash 掉了，继续显示等于骗人。
- **被踢降级到只读**：网关在保存被 app 回 403 时广播 `collab-save-error`、随后 `close(4403)`。**不能只看状态码**：hocuspocus 把 CLOSE 消息合成 `code: 1000` + 原始 reason，因此判据是 reason 里的"写入权限已吊销 / 已被移出协作会话"。`collabKickReason` 与 `saveErrorIsKick` 把这条判断收成纯函数并有单测——猜错的方向很危险：把普通断线当成被踢，用户以为权限没了；反过来被踢了还当 live 编辑，写的字永远发不出去。降级只降不升，重连不会自动变回 live。
- **保存失败要收尾**：网关回 `collab-save-error`（只读、内容过大、后端 5xx）时不广播成功，界面必须停掉"保存中"并显示原因，否则按钮会一直转。
- **`seed` 有了显式入口**：「以本地为准」把编辑器里那份内容作为会话首帧写进共享文本，并立刻存一次草稿提交（草稿分支上的提交可回滚）。它只在**没人在线**时出现——预检的处置列表给不给这一项就由 `peersKnown && peers === 0` 决定，界面不另算一遍。感知不可用时按有人在线处理：拿本地内容开新文档会把别人的内容顶掉，而 join 猜错只是白等一次同步。
- **播种必须等同步完成**：`collabStatus === "connected"` 只表示 socket 连上，此时服务端的 Yjs 状态可能还在路上。实测在这之前替换共享文本，本地插入会与服务端随后合并进来的内容叠成重复文本（行数从 92 变成 183）。因此改为等 provider 的 `onSynced`，`replaceCollabText` 也在一次事务里先删后插——分两次会让别人在中间那一帧看到空文档。

- 系统通知走 Wails 的 `notifications` 服务：`NotificationService` 暴露申请授权、查询授权、发送与**带动作按钮发送**四条路径，全部在 Go 侧就位并有单测（含"未接线时明确失败"与"校验不通过不触碰系统通知中心"）。
- 授权只在用户显式点击左轨的通知开关时申请。启动就弹授权请求时，用户还不知道会收到什么，拒绝一次之后系统就很难再让他改回来。
- **通知里可以直接批准**：`RegisterNotificationCategory` 注册动作组 → `SendNotificationWithActions` 发出带按钮的通知 → `OnNotificationResponse` 收回用户的响应。响应经 `notification:activated` 事件回到界面，界面再走评审窗同一条 `submitPrReview` 路径——Go 侧只交"哪个按钮、哪条通知、什么附加数据"，权限与后果仍由服务端裁决。三条刻意的约束：按钮最多三个（系统上限，多了会被静默截断）、ID 不能重复（重复让点击结果二义）、点通知正文时把系统回的 `DEFAULT_ACTION` 归一成空串（界面才能区分"他点了正文"与"他按下了批准"）。
- **哪些通知值得弹由数据决定**：`approvalTarget` 只在通知未读、目标类型是 `pull_request`、且带仓库与正整数编号时才给批准按钮；缺一项就不给——猜一个 PR 去批准比不动作危险得多。弹过的 id 在内存里记一份，否则每次列表重取都会重弹同一条。

## 已知取舍

- **凭据机制与设计文档 §9 不同，是有意的**：设计里写的是随应用带一个 `kustos git-credential` 子命令当 `credential.helper`，由 Go 经 stdin 交令牌。实现改成 `GIT_CONFIG_*` 环境变量注入（clone 与 push/fetch 同一套），理由有二：helper 是全局配置，替用户写一条进他的 gitconfig，副作用比一次性环境注入大得多；而且 helper 拿不到"这条命令要访问哪个远端"的上下文，作用域收敛反而更难写对。Basic 形态试过不成立的原因见上面克隆那一节。
- **不做文件监听**。设计文档 §9 写了 `fsnotify` + 去抖，实现里没有任何 watcher，这是裁决而不是遗漏：本地状态的刷新走三条现成的路——窗口聚焦时重取（`refetchOnWindowFocus`）、每个动作之后精确失效对应查询、状态条上那个手动刷新按钮。代价是"用户在外部编辑器改了文件、桌面端不知情"，直到他切回来或点刷新。做 watcher 要连带决定溢出降级、大仓库阈值、`.git`/`node_modules` 过滤，而它换来的只是把这几秒的滞后抹平；M2 的验收口径是"改 + 推 + 评闭环、行为与终端一致"，这条不卡那个闭环。真要做时按设计文档的阈值与降级方案补齐，不要只挂个 watcher 假装实时。
- **服务绑定面按实际需要生长，尚未拆到设计文档里那种一服务一职责的粒度**。设计文档列了 10 个服务，当前有 `SessionService`、`WorkingCopyService`、`WindowService`、`NotificationService`、`LSPService`、`SystemService` 与 `OfflineCacheService` 七个；`FileDiff`、`ListChanges`、`ReadText`/`WriteText`、`StageHunk`/`UnstageHunk`、`RemoteInfo`、`OpenInEditor`、`RevealInFileManager`、`LoadCodeLayout`/`SaveCodeLayout`、`CloneRemote`/`CancelClone` 都挂在 `WorkingCopyService` 上。后续能力变多时再按"用户能感知的本地能力"拆开。
- **系统集成不做跨平台假装支持**。`shellreg` 在非 Windows 平台提供同签名的空实现，但**必须报错而不是静默成功**：静默成功会让界面显示"已开启"，而重启之后什么都不会发生。真正的实现属于各自的打包阶段（Linux 的 `.desktop`、macOS 的 plist + `open`）。
- **通知动作不在 Go 侧执行**。Go 只回传"哪个按钮、哪条通知、什么附加数据"，动作由界面走既有接口完成——权限、目标是否仍然有效都由服务端裁决。桌面端不因为多了一个通知按钮就多出一条旁路。
- **自动更新未做，且不是"接一下就行"**。它要连带决定签名、安装器、回滚与"更新失败时如何不把用户卡在半新半旧的状态"，而仓库现在连签名与三平台打包都没有（见"发布"）。先做更新通道等于在一条没有验收标准的路上跑。
- **窗口后端、目录选择与实例凭据的接线都用包级函数而非服务方法**。绑定生成器会把服务上所有导出方法都变成前端可调用的接口，接线函数一旦是方法，前端就能改写本机的窗口后端、目录选择器，或把联网 git 的凭据换成任意值。因此 `BindWindowBackend`、`BindDirectoryPicker`、`BindCloneProgress`、`BindInstanceAuth` 都是包级函数；`SystemService` 上只留两个真正要被界面调用的动作（查 git 状态、请用户选目录）。
- **联网 git 的凭据是现取的，不缓存**。`BindInstanceAuth` 每次发起 clone/push/fetch 时回问 `SessionService`，因为一次操作可能跑几分钟，期间令牌会 refresh。三条链路共用这一份 provider：它们回答的是同一个问题（我是谁、访问哪台实例），各存一份迟早漂移。
- **全文搜索不建索引，也不进工作树锁**。每次查询现扫工作树，结果永远与磁盘一致；代价是宽泛查询可能慢，用逐文件上限、总上限与流式提前终止兜住。`git grep` 只读，把它挡在提交与暂存前面是纯粹的伤害——所以它不与 git 命令共用那把工作树锁。
- **Go 侧不做业务判断**。权限与合并策略一律回服务端，Go 只回答"本机是什么状态"。
- **只读与只写单一真相**。磁盘模式下手动保存，不存在"自动保存到远端"的路径；协作模式把真相挪进共享文本、只在退出时写回缓冲区，两条路径靠模式互斥，不会双写。
- **协作要信任网关的 awareness 盖章**。协作光标与在线人数都以网关广播的身份为准（网关用连接令牌里的 `user_id` / `name` 覆盖客户端自报的字段），桌面端只决定颜色与光标位置——自己判身份等于给冒名留口子。
- **草稿领先只读不写**。`DraftAhead` 只比较本地已有的引用，不 fetch：进入协作的预检不该在用户改到一半时动网络或工作树。代价是"别人刚保存但本地还没 fetch"的草稿看不到，要等下一次 fetch。
- **信任按"路径 + 远端来源"记，不按仓库身份记**。设计文档要求"路径变化、切仓库、远端 origin 变化都要重新确认"，当前路径与 origin 两维都做了：`workspace_trust` 存下做决定时的 `origin`，远端改指到别的仓库后旧信任失效、需要重答。做不到的是"同一个 origin 换了地址写法"（`git@` 与 `https://` 指向同一仓库会被当成两处来源）与"往这个目录里塞进别的来源的代码"——前者只能再问一次，后者要内容哈希才判得出来，成本远超收益。
- **管理控制台不做**。网关按来源白名单拦掉 `/api/app/`，桌面端出口地址不可控，结构上过不去。
- **mtime 用毫秒而非纳秒**。纳秒时间戳超出 JS 的安全整数范围（`Number.MAX_SAFE_INTEGER`），经绑定层往返会被舍入，导致冲突检测永远失败。已有测试守住这个单位。
- **拉子进程一律隐藏控制台窗口**（`internal/platform/noconsole`）。桌面端是 GUI 子系统进程，每次 `exec` 控制台程序都会新建一个窗口；状态轮询与行标刷新频率很高，不隐藏就是连续闪黑框。git、`git apply`、语言服务器、外部编辑器与文件管理器打开都走这一个助手。

- **离线缓存的真机取样**：Inbox 拉到一次之后直接调 `OfflineCacheService.Get`，拿到 `found=true`、payload 可解析、时间戳是毫秒级（`fetchedAt > 1e12`）。界面回落那一支需要真实断网，只用单测覆盖了"过期即删""缓存键选择"这类可判定的部分。
- 克隆的端到端有自己的取样方式：系统目录选择框是原生窗口，CDP 点不到，所以脚本在页面里 `import('/wails/runtime.js')` 拿 `Call`/`Events`，直接调 `WorkingCopyService.CloneRemote` 并订阅 `clone:progress`——这与面板走的是同一条桥、同一个服务方法，只是"用户选了哪个目录"这一步由脚本给出。真实跑一次拿到 169 条进度事件，落盘后核对 `git status` 干净、`origin` 是实例地址、**`.git/config` 里没有令牌**。
- push/fetch 凭据的端到端**必须打在私有仓库上**：公开仓库匿名也能读写，测不出令牌到底有没有用上。验收机不配置任何 git 凭据（无 `credential.helper`、无 PAT），于是"成功"与"没弹 Git Credential Manager 窗"是同一个事实的两面——一旦弹窗，就说明那条命令根本没拿到凭据。真实链路：引导里连接与登录 → 克隆私有仓库 → `ReadText` 读 README 拿 mtime → `WriteText` 写回 → 暂存 → 提交（`ahead=1`）→ `Push` 成功且 `ahead=0` → `Fetch` 成功 → 核对服务端 `refs/heads/main` 就是桌面端那个提交、`.git` 全树搜不到令牌。建立上游那条也在真机验过：用底层 git 造一个无上游分支（桌面端故意没有 `checkout -b` 能力，造场景在脚本外、被测的仍是服务方法），`PushCommand` 如实给出 `git push --set-upstream origin <分支>`，执行后本地上游与服务端分支都在。
